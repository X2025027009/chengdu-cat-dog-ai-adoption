## 二、不要改动 `release/`（它由委托方负责）

**分工说明**：你负责本地代码，`release/` 发布源的同步与云端部署
由委托方统一处理。请不要修改、复制或删除 `release/` 下的任何文件。

原因有两点：

1. 部署需要云端凭证与一套固定流程（同步发布源 → 部署 → 校验线上哈希），
   由固定一方执行出错率最低；
2. 两个人同时动发布源，容易出现「谁覆盖了谁」而看不出来。

所以你新增的 `about.html`、`admin.html` 等页面，**保留在根目录即可**，
委托方会在部署前统一同步到 `release/`。

**你需要注意的是**：新增页面使用了共享资源（如 `styles.css`、`site-config.js`），
请确认这些资源用相对路径引用，不要写 `/styles.css` 这样的绝对路径——
发布源是 `release/` 目录，绝对路径在上线后会指向错误位置。

## 三、ESLint 不通过（9 个错误）

```bash
npm run lint
```

报错全部是 `no-undef`：`window`、`document`、`location` 未定义。

原因在 `eslint.config.mjs` 第 34 行：

```js
files: ['app.js'],
```

只把 `app.js` 当作浏览器脚本，新增的 `site-config.js` 落在覆盖范围之外，
被当成默认环境检查，于是浏览器全局变量全部报未定义。

请把站点侧脚本纳入同一组（新增页面若还有别的脚本也要一并纳入）：

```js
files: ['app.js', 'site-config.js'],
```

改完确认：

```bash
npm run lint     # 期望 0 problem
```

**规范要求「代码风格遵循主流规范」，lint 必须干净。**
如果后续还会新增站点脚本，建议直接写成 `'*.js'` 并在忽略列表里排除
`tools/`、`functions/`，避免每加一个文件都要改配置。
