## 一、素材体积过大，影响首屏加载

### 实测数据

`assets/` 合计 **19.9 MB**，全部会随首屏或滚动加载。逐项实测：

| 文件 | 体积 | 引用次数 |
| --- | --- | --- |
| `assets/real/courtyard-black-dog.png` | 3.14 MB | 1 |
| `assets/real/courtyard-brown-dog.png` | 3.03 MB | 1 |
| `assets/real/courtyard-white-dog.png` | 2.82 MB | 1 |
| `assets/real/courtyard-cat.png` | 2.78 MB | 1 |
| `assets/brand/companions.png` | 1.82 MB | 2 |
| `assets/brand/admin-play-and-stretch.png` | 1.51 MB | 2 |
| `assets/brand/admin-cushion-peek.png` | 1.46 MB | 1 |
| `assets/brand/adoption-companions.png` | 1.46 MB | **0（未被任何页面引用）** |
| `assets/brand/admin-walk-together.png` | 1.04 MB | 1 |
| 其余（含 SVG） | 合计约 1.2 MB | — |

### 问题

**照片存成了 PNG。** PNG 是无损格式，适合图标与线条图，照片用它会大出十倍以上。
四张 `courtyard-*.png` 各接近 3 MB，合计约 12 MB，是体积的主要来源。

**这直接影响「用户体验」评分**（权重 10%）：移动网络下首屏要等十几秒，
再好的设计也感受不到。

### 要求

1. **把照片类资源转为 WebP（质量 85 左右）**，包括四张 `courtyard-*`
   与 `brand/` 下的照片型插画。转换后同步更新 HTML/CSS 中的引用路径。
2. **SVG 保持不动**——它们本来就小，也不必栅格化。
3. **删除零引用的 `assets/brand/adoption-companions.png`。**
   如果它其实是有意保留的备用素材，说明原因并移到仓库外，不要留在发布素材里。
4. 转换后**逐一核对引用仍然有效**，并在 `check-multipage.cjs` 或新的检查里
   补一条：**页面引用的素材必须真实存在**（现在只检查页面结构，不检查素材引用）。

**验收标准**：`assets/` 总体积降到 **3 MB 以内**，页面视觉无可察觉的差异。
改完请报告转换前后的实际体积对比。

### 提醒

转换前先确认这些图是否有原始素材可重新导出。**不要用低质量方式反复压缩**——
从 3 MB 的 PNG 转成 WebP 是重新编码一次即可，不要多次有损压缩。
